    How the report is counted
    • Counting unit. One Monday parent item per milestone in the selected dates. A single task can contain several masters, hooks, variants, or placements. The report uses parent work packages for totals. Planned images are summed only where the title explicitly declares an image count.
    • Intake. Added uses the item creation timestamp. Briefed uses Brief Date, with a transition to Brief Ready as fallback when the date is blank. Queued uses entry into Ready for Editing or Queued for Editing from outside those two statuses. Returns from Editing or a later production stage appear under Returned to queue.
    • Production. Editing started uses entry into Editing, including resumed work. Edits delivered uses Delivery Date or entry into In Review. Approved uses entry into Approved. Each creative can count at multiple milestones.
    • Launch. Launched uses Launched Actual Date first and a transition to Launched when the date is blank. The count reflects Monday’s launch records.
    • Open work. Production pipeline shows each active item’s current Monday status, including creator work, review, approval and upload. The pipeline reflects the snapshot date. Use the Launched milestone for launches within the selected dates.
    • Classification. IMG = Static; VID and VSL = Video; GIF, carousel and catalog have their own categories. Explicit creator sourcing/filming tasks and brief rows have a dedicated view. Untyped rows are available under Unclassified intake. Blank awareness is Unclassified. Target personas come from the matched creative brief or its testing-plan tab. Persona groups use the ad’s product division. Counts distinguish personas named in briefs from those inferred from product-specific copy. A shopper can buy for another person. The creative details show the source and note any explicitly named secondary target. Seasonal grouping uses the Campaign field and explicit titles when Campaign is blank or Evergreen.
    • Source coverage. Milestone timestamps use Eastern Time. Format, tags, owners, due dates, and displayed statuses are board values at the snapshot. Active backlog uses that same snapshot for any date selection.
